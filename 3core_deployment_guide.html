Part 1

Before you start

A 60-second prep so you don't get stuck halfway through.

What you need

  • A working email address you can check during setup (you'll receive verification emails from each service).
  • A web browser — Chrome, Edge, or Firefox. Anything modern.
  • A GitHub account — free. If you don't have one, no problem; we'll walk you through signing up at the start of Part 4. Signing up takes about 60 seconds when you use a Google account.
  • A phone that can receive SMS — Backblaze sometimes asks for a one-time verification code, depending on your account. You may or may not be prompted. Have a phone nearby just in case.
  • About one hour of uninterrupted time the first time you do this. Subsequent deployments take less than 15 minutes.
Good news None of the three services require a credit card. The free tiers used here cover small-to-medium internal use indefinitely.

The shape of what we're building

The 3CORE Portal is made of three moving parts. They live on three different free services. Your only job in this guide is to wire the three together by copying a handful of values from one place to another.

PartWhat it doesWhere it lives
File storageHolds documents users uploadBackblaze B2
DatabaseHolds users, projects, tasks, audit logNeon
ApplicationThe website itself + the engine behind itRender

The notepad

Open a blank text file on your computer now. Title it 3CORE Deployment Values. By the end of Part 3 it will contain these eight values:

B2 Endpoint URL      : (filled in during Part 2)
B2 Region            : (filled in during Part 2)
B2 Key ID            : (filled in during Part 2)
B2 Application Key   : (filled in during Part 2)
B2 Bucket Name       : (filled in during Part 2)

DATABASE_URL         : (filled in during Part 3)

ADMIN_INITIAL_PASSWORD : (you choose — write it here so you don't forget it)
SEED_PM_PASSWORD       : (you choose — same thing)

Treat this file like a password. Don't email it, don't paste it into chat, and delete it after deployment is complete.

Part 2

Backblaze B2 — File storage

Backblaze stores every file your users upload through the portal: PDFs, photos, drawings, signed documents. The free tier gives you 10 gigabytes — enough for tens of thousands of typical office documents.

Step 2.1

Create the Backblaze account

  1. Open https://www.backblaze.com/sign-up/cloud-storage in your browser.
  2. Enter your email address and a strong password. Click Sign Up.
  3. Backblaze emails you a verification link. Open the email and click it.
Step 2.2

Enable B2 Cloud Storage on your account

  1. After login you'll see the Backblaze dashboard. Look for a banner or button labelled Enable B2 Cloud Storage and click it.
  2. Backblaze may ask for "Mobile Verification" at this point — not every account is prompted. If you see the prompt, enter your phone number, click Send Code, wait for the SMS, type the code in, click Verify. If you don't see this prompt, just move on.
  3. The left-hand sidebar now shows B2 Cloud Storage as a section. You are ready to proceed.
If you don't see "Enable B2" Your account may already be enabled. Look for "Buckets" in the left sidebar — if it's there, skip to step 2.3.
Step 2.3

Create a bucket (a folder in the cloud)

A "bucket" is just a named container that holds files. We'll make one bucket for the entire 3CORE portal.

  1. In the left sidebar, under B2 Cloud Storage, click Buckets.
  2. Click the blue Create a Bucket button at the top.
  3. Fill in the form exactly like this:
    • Bucket Unique Name: 3core-storage

      If Backblaze says the name is taken, add a suffix: 3core-storage-acme, etc. Bucket names are globally unique across all Backblaze customers.

    • Files in Bucket: select Private. Do not pick "Public".
    • Default Encryption: Disable.
    • Object Lock: Disable.
  4. Click Create a Bucket. You'll land on the bucket's details page.
Step 2.4

Save the Endpoint URL and Region

On the bucket details page, find the row labelled Endpoint. It will look something like:

s3.us-east-005.backblazeb2.com
  1. Copy the entire endpoint string into your notepad on the line B2 Endpoint URL. (Later you will prefix it with https:// — for now save it as shown.)
  2. The endpoint contains the region. In the example above the region is us-east-005. Copy just the region part into your notepad on the line B2 Region.
  3. Also write the bucket name you chose into your notepad on the line B2 Bucket Name.
Step 2.5

Create an Application Key (the password for the app)

An Application Key is what 3CORE will use to read and write files in your bucket. Think of it as a username and password specifically for software.

  1. In the left sidebar, click Application Keys.
  2. Click Add a New Application Key.
  3. Fill the form:
    • Name of Key: 3core-app
    • Allow access to Bucket(s): select the bucket you created in step 2.3 (do not leave it as "All").
    • Type of Access: Read and Write.
    • Leave File name prefix and Duration blank.
  4. Click Create New Key.
Step 2.6

Copy the key values — this page shows them only once

Stop and read this before clicking anything else Backblaze shows you the secret part of the key one time and one time only. If you close this page without copying it, the secret is gone and you'll have to delete the key and make a new one. Don't navigate away until both values are in your notepad.

The page now shows two boxes:

  • keyID — a short string starting with a digit, around 25 characters. Copy it into your notepad on the line B2 Key ID.
  • applicationKey — a longer string starting with K005 (or similar), around 31 characters. Copy it into your notepad on the line B2 Application Key.

Once both are in the notepad, you may close the page.

End of Part 2 — your notepad should now contain

  • B2 Endpoint URL — e.g. s3.us-east-005.backblazeb2.com
  • B2 Region — e.g. us-east-005
  • B2 Key ID — the short string
  • B2 Application Key — the long string starting with K005
  • B2 Bucket Name — e.g. 3core-storage
Part 3

Neon — Database

Neon hosts the database that stores your users, projects, tasks, expenditures, and audit log. The free tier gives you half a gigabyte, which holds tens of thousands of records.

Step 3.1

Sign up

Neon offers several sign-in options. If you already created a GitHub account (see Part 4 below), use Continue with GitHub — using the same login for all services keeps things tidy. If not, Continue with Google works just as well and is the fastest path.

  1. Open https://neon.tech in your browser.
  2. Click Sign up in the top right corner.
  3. Click Continue with GitHub (if you have one) or Continue with Google.
  4. Approve the permission prompt.
Step 3.2

Create a project

After login you'll see a "Create your first project" screen.

  1. Project name: 3core
  2. Postgres version: leave the default (whichever number is preselected).
  3. Cloud provider: leave default (AWS).
  4. Region: choose AWS US East (Ohio). This will sit close to Render's default region, keeping the app fast.
  5. Click Create project.
Step 3.3

Copy the connection string

Immediately after the project is created, Neon shows a box titled Connection string. It has two tabs: Pooled connection and Direct connection. The Pooled one is selected by default — that's the one we want.

  1. Click the small copy icon next to the connection string.
  2. Paste it into your notepad on the line DATABASE_URL. It will look roughly like this:
postgresql://3core_owner:abc123def@ep-cool-name-12345-pooler.us-east-2.aws.neon.tech/3core?sslmode=require
Why "pooled"? Neon's free tier sleeps when no one is using it. The pooled connection wakes the database faster and handles multiple simultaneous users better. Always use this one unless told otherwise.

End of Part 3 — your notepad should now also contain

  • DATABASE_URL — the long postgresql://... string from Neon
Part 4

Render — Hosting

Render runs the 3CORE Portal itself. You'll set up two pieces here: a backend (the engine that talks to Backblaze and Neon) and a frontend (the website your users open in their browser).

Step 4.1

Create a GitHub account (skip if you already have one)

GitHub is where the 3CORE source code lives. Render needs to read code from GitHub to deploy your app, so you need a GitHub account. Signing up takes under a minute when you use your Google account.

  1. Open https://github.com/signup in your browser.
  2. On the very first screen GitHub asks for an email address. Below the email field, click the link "Continue with Google".

    If you don't see "Continue with Google" immediately, type your Google email address into the email field and click Continue — GitHub will then offer to link your Google account.

  3. A Google sign-in window appears. Choose the Google account you'd like to associate. Approve the permission prompt.
  4. GitHub will ask you to pick a username. Pick something short, all-lowercase, no spaces. Write this username down — you'll see it in URLs later.
  5. GitHub may send a one-time code to your email to confirm. Open the email and enter the code.
  6. You're done. You should now be on the GitHub home page.
Why GitHub? GitHub stores the 3CORE source code. Render reads code from GitHub when deploying. You don't need to learn GitHub for anything else — just sign in and click "Fork."
Step 4.2

Fork the 3CORE repository to your account

"Forking" means making your own personal copy of the 3CORE code on your GitHub account. You need your own copy because Render will deploy from it.

  1. Make sure you're still signed into GitHub. If not, sign in at https://github.com.
  2. Open https://github.com/Past-da-king/3CORE in your browser.
  3. In the top right of that page, find the Fork button (it's next to "Star" and "Watch"). Click it.

    If you see a dropdown menu after clicking, just pick your own account name from the list.

  4. A "Create a new fork" page appears. Leave all defaults as they are. At the bottom, click the green Create fork button.
  5. Wait 3–5 seconds. The page reloads and you'll now be at a URL like https://github.com/YOUR-USERNAME/3CORE. That's your personal copy.
How to confirm the fork worked Look at the top of the page. You should see YOUR-USERNAME / 3CORE — and just under it, a small note saying "forked from Past-da-king/3CORE." If both are there, you're good.
Step 4.3

Create the Render account

  1. Open https://render.com in your browser.
  2. Click Get Started for Free in the top right.
  3. Choose Sign in with GitHub. Use the GitHub account you just created (or already had).
  4. Render asks for permission to read your GitHub repositories. Click Authorize Render.
Step 4.4

Tell Render to set up both services at once (Blueprint)

The 3CORE repository contains a file called render.yaml that describes both services. Render can read this and create everything in one click.

  1. Go to your Render dashboard (https://dashboard.render.com).
  2. Click the blue New + button in the top right.
  3. Choose Blueprint from the dropdown.
  4. If asked, click Configure account to grant Render access to your forked 3CORE repository. On the GitHub page that pops up, choose Only select repositories, pick 3CORE, click Save.
  5. Back on Render, find 3CORE in the repository list and click Connect.
  6. Render reads render.yaml and shows two services that will be created: 3core-api (the backend) and 3core-portal (the frontend).
  7. Click Apply.
The first build will fail — that's normal Render will start building both services but the backend will refuse to start because the secret environment variables aren't filled in yet. We fix that in the next step.
Step 4.5

Fill in the backend's environment variables

The backend needs the values from your notepad. We paste them in now.

  1. On the Render dashboard, click the 3core-api service.
  2. In the left sidebar of that service's page, click Environment.
  3. You'll see a list of environment variables. Some are pre-filled (don't touch those). The ones marked "Required" or showing an empty value are what you need to fill in.

Use this table — paste the value from your notepad into each variable:

Variable name on RenderWhat to paste from your notepadNotes
DATABASE_URL The Neon connection string Paste exactly, including the trailing ?sslmode=require
B2_ACCESS_KEY_ID B2 Key ID Short string from Backblaze step 2.6
B2_SECRET_ACCESS_KEY B2 Application Key Long string starting with K005
B2_ENDPOINT_URL https:// + B2 Endpoint URL You must prefix with https://. Example: https://s3.us-east-005.backblazeb2.com
B2_REGION B2 Region e.g. us-east-005
B2_BUCKET_NAME B2 Bucket Name e.g. 3core-storage
ADMIN_INITIAL_PASSWORD Pick a strong password You'll use this for the very first login. Write it in your notepad.
SEED_PM_PASSWORD Pick another strong password Optional. Only used if you run the example seed script.
SECRET_KEY Leave alone Render generates this automatically.

When all rows are filled, scroll down and click Save Changes. Render will start redeploying the backend with the new values.

Step 4.6

Match the frontend's API URL to the backend's address — important

The frontend is just a web page; it needs to know which URL to call for the backend. By default the template assumes the backend is named 3core-api and lives at https://3core-api.onrender.com. If your services have different names, this URL has to change.

  1. In Render's dashboard, click the 3core-api service. At the top of its page you'll see its public URL — something like https://3core-api.onrender.com or https://3core-api-xyz.onrender.com. Copy this URL exactly.
  2. Now go back to the dashboard and click the 3core-portal service.
  3. In the left sidebar of the portal service, click Environment.
  4. Find the row VITE_API_URL. Click Edit.
  5. Paste the backend URL you copied. No trailing slash. Correct: https://3core-api.onrender.com. Wrong: https://3core-api.onrender.com/.
  6. Click Save Changes. The frontend will redeploy.
Why this matters If VITE_API_URL doesn't match the actual backend URL, every action in the portal (login, viewing projects, uploading files) will silently fail. Browser developer tools will show "404 Not Found" or "Failed to fetch". This is the single most common cause of a broken deployment — double-check this value.
Step 4.7

Tell the backend it's safe to accept requests from the frontend (CORS)

The backend has a safety check that only accepts traffic from approved websites. You need to add your frontend's URL to that approved list.

  1. Click the 3core-portal service. At the top of its page, copy its public URL — something like https://3core-portal.onrender.com.
  2. Go back to the dashboard and click 3core-api → Environment.
  3. Find the row CORS_ORIGINS. Click Edit.
  4. Replace the value with your portal URL. No trailing slash. Example: https://3core-portal.onrender.com.
  5. If you want to also allow local testing from your laptop, separate values with commas: https://3core-portal.onrender.com,http://localhost:3000
  6. Click Save Changes.
Step 4.8

Wait for both services to finish deploying

  1. Click 3core-api and watch the Logs tab. The backend is ready when you see a line like Uvicorn running on http://0.0.0.0:10000.
  2. Click 3core-portal. Wait until its status badge (top of the page) turns green and says Live.

Typical deploy time is 3 to 10 minutes for each service. Both can deploy at the same time.

Step 4.9

Create the database tables and the admin user (one-time)

Your Neon database is empty. We need to create the tables and the very first admin user. The 3CORE code has a script for this; you'll run it once from inside the backend service.

  1. Click 3core-api. In the top tabs of its page, click Shell.
  2. A terminal opens inside the backend's server. At the prompt, type:
python init_db.py

Press Enter. You should see:

Creating database tables...
Creating admin user...
Database initialized.

If you see this, your database is ready. Close the Shell tab.

Need to do it again? Running this script a second time will not duplicate the admin user — it skips creation if one already exists. So if you ever need to reset, first remove the admin row from Neon's SQL Editor, then run the script again.

End of Part 4 — what's live

  • Portal (your users open this): https://3core-portal.onrender.com (or your custom name)
  • API (technical / for debugging): https://3core-api.onrender.com
  • Database is initialized; admin user exists.
  • Files uploaded through the portal go to your Backblaze bucket.
Part 5

First login & basic admin

A short checklist for the first time you open the live portal.

Logging in for the first time

  1. Open the portal URL (e.g. https://3core-portal.onrender.com) in your browser.
  2. Username: admin
  3. Password: the ADMIN_INITIAL_PASSWORD you set in step 4.5.
  4. Click Sign In.
Change the admin password immediately The password you set in Render's environment variables is also visible to anyone who has access to your Render dashboard. As soon as you log in, change it to something only you know.

Steps to take right after first login

  1. Change the admin password. Click your name/avatar in the top right → User Settings → set a new password.
  2. Add real users. Open System Administration from the sidebar → Add User. Set the role appropriately:
    • admin — full control, can add users and delete projects
    • pm — project manager: can create/edit projects they're assigned to
    • team — regular team member: can update tasks they're assigned to
    • executive — read-only oversight across all projects
  3. Create your first real project. Either manually via Project Setup, or import an Excel using the Excel Import tab.
Part 6

Troubleshooting

Specific symptoms and what to check.

"I open the portal and it loads but login fails"

  • Make sure you're using the exact ADMIN_INITIAL_PASSWORD from Render. Passwords are case-sensitive.
  • If that's correct, the most likely cause is that VITE_API_URL on the frontend doesn't match the backend's real URL. See step 4.6.
  • Open the browser's developer tools (F12) → Network tab → try to log in again. If you see red rows pointing at the wrong URL, fix VITE_API_URL.

"I get a CORS error in the browser console"

  • The backend's CORS_ORIGINS doesn't include the frontend URL. See step 4.7.
  • Make sure there's no trailing slash on either URL.
  • Save changes on Render and wait for the backend to redeploy (about 2 minutes).

"The app loads but I can't upload files"

  • One of the four Backblaze values is wrong. Re-check them in Render's Environment page against your notepad.
  • Common mistakes:
    • B2_ENDPOINT_URL missing the https:// prefix.
    • B2_REGION includes extra characters or doesn't match the endpoint.
    • B2_BUCKET_NAME has a typo.
  • Open 3core-api → Logs tab. Try an upload from the portal. Errors with botocore in the line are Backblaze problems and the error message often tells you exactly what's wrong.

"The first request after a quiet period is slow"

On Render's free tier, services sleep after 15 minutes of no traffic. The first request after a sleep takes 30–60 seconds to wake everything up. Subsequent requests are fast. Upgrade to a paid plan to remove this behavior.

"I lost the admin password"

  1. Open Neon's dashboard → click your project → SQL Editor.
  2. Run: DELETE FROM users WHERE username = 'admin';
  3. Go to Render → 3core-api → Environment → change ADMIN_INITIAL_PASSWORD to something new → Save.
  4. After the backend redeploys, open Shell and run python init_db.py again.

"How do I see what users are doing?"

Once logged in as admin, open Monitoring from the sidebar — every login, upload, project change, and deletion is logged there with timestamp and user.

"Render says I've hit a build limit"

Free tier accounts get 500 build minutes per month. A 3CORE deployment uses about 5 minutes of build time. If you're hitting limits, you're probably redeploying too often by accident — check that automatic deploys aren't triggering on every tiny git push.

Appendix

Glossary

Plain definitions of the technical words you'll see while doing this.

TermPlain meaning
BucketA named folder in cloud storage that holds files. Backblaze and other cloud-storage services use this term.
CORS"Cross-Origin Resource Sharing." A browser safety check that stops random websites from making requests to your backend. You tell the backend which websites are allowed — only those will work.
Connection stringOne long line of text that contains everything needed to connect to a database: the host, port, username, password, and database name, all in one URL.
EndpointThe web address of a service. Backblaze calls its storage server's web address an "endpoint."
Environment variableA name-value setting that you give a piece of software when it starts. It's a way to store secrets and configuration outside the code.
ForkTo make your own personal copy of someone else's GitHub repository. Your copy is independent and you can change it freely.
Frontend / BackendThe frontend is the website your users see and click on. The backend is the engine behind it that talks to the database and storage. They are separate programs.
Postgres / PostgreSQLA specific kind of database. Neon is a hosted Postgres service.
Pooled connectionA way of connecting to a database that's better at handling multiple users at the same time and waking the database up faster. Always preferred for web apps on serverless databases.
Render BlueprintA feature where Render reads a configuration file in your repository and creates all the necessary services automatically.
RepositoryA folder of code stored on GitHub. 3CORE is one repository.
ShellA text-based way to type commands directly into a running server. Render gives you one for each service.
SigV4The cryptographic method used to prove a request is authorized when talking to S3-compatible storage like Backblaze. You don't need to understand it; it just needs to work, which it will if the four B2 values are correct.
